# TikTok LIVE ツール

STE（StreamToEarn）と LiveSpark の機能を1つにまとめる、自分専用の TikTok LIVE 配信ツールです。
月額0円で動き、配信のデータ（配信時間・来た人・ギフトや行動）を配信PCの中に貯めて、分析にも使えます。

- 仕様：[REQUIREMENTS.md](REQUIREMENTS.md)（要件定義書）
- Claude Code 向けのメモ：[CLAUDE.md](CLAUDE.md)
- データベースの説明：[docs/database.md](docs/database.md)

**今の段階：フェーズ0（試作）** … TikTokにつながるか・演出が出るか・Minecraftと読み上げが動くか・記録が貯まるかを確かめる段階です。
「きっかけ→やること」を自由に組むルールや、スピナーなどはフェーズ1で作ります。

---

## できること（フェーズ0）

- 起動すると自動で「配信待ち」になり、配信が始まったら自動でつながる。切れたら自動でつなぎ直す
- 届いたイベント（ギフト・いいね・コメント・フォロー・シェア・サブスク・入室・視聴者数）を管理画面に表示
- ギフトが来たら：アラートをOBSに表示／Minecraftにコマンドを送る／VOICEVOXで読み上げる
- すべての配信のデータをデータベースに記録（テストは「テスト」の印を付けて分ける）
- テストパネルで、にせのギフトやコメントを起こして確かめられる
- Euler Streamの使用回数を数えて、無料枠（1日2,500回）の8割で注意

## はじめての準備

1. **Node.js** の LTS 版をインストールする（インストーラーは「次へ」のままでOK）
2. このプロジェクトをダウンロードする。PowerShell（またはClaude Code）で：
   ```
   cd $HOME
   git clone https://github.com/winter020677/music-is-my-lielife.git tiktok-live-tool
   ```
   ※ リポジトリの名前を変えた時は、URLもそれに合わせる
3. できたフォルダ（例：`C:\Users\あなた\tiktok-live-tool`）の **`setup.bat`** をダブルクリック
   - 必要な部品のダウンロードと、管理画面の準備をします（数分かかります）
   - 終わると、デスクトップに **「TikTok LIVE ツール」** のショートカットができます
4. デスクトップの **「TikTok LIVE ツール」** をダブルクリック → 管理画面のウィンドウが開く
5. 管理画面の **「設定」** で：
   - 「TikTokのユーザー名」を入れる
   - 「秘密情報」に **Euler StreamのAPIキー** を入れて「秘密情報を保存」
   - 画面の上の「保存」を押す
6. 管理画面の **「オーバーレイ」** に出ているURLを、OBSのブラウザソースに入れる（下の「OBSに入れる」）

## 起動と終了

- **起動**：デスクトップの「TikTok LIVE ツール」をダブルクリック（黒い画面は出ません）
  - 管理画面のウィンドウを閉じても、本体は動き続けます（記録も続きます）
  - もう一度ダブルクリックすると、管理画面のウィンドウだけが開きます
- **終了**：管理画面の右上の「終了」ボタン

配信の記録を取りこぼさないように、**配信する日は、配信を始める前に起動しておいてください**（起動していれば、配信が始まった時に自動でつながります）。

## OBSに入れる

OBSの「ソース」の＋ →「ブラウザ」を追加して、URLと大きさを入れます。

| オーバーレイ | URL | 大きさ | 注意 |
|---|---|---|---|
| アラート | `http://127.0.0.1:3939/overlay/alert/` | 1920 × 1080 | |
| 読み上げ（音だけ） | `http://127.0.0.1:3939/overlay/speech/` | 300 × 100 | 「OBSで音声を制御する」にチェック |

- 背景は透明なので、画面の上に重ねられます
- 本体を再起動しても、オーバーレイは自動でつなぎ直します（URLを貼り直す必要はありません）
- 見た目は `overlays\alert\style.css` を書き換えると変えられます（値を直接書いてあります）。書き換えたら管理画面の「全部を再読み込み」

## Minecraft の準備

1. Minecraftサーバーのフォルダの `server.properties` をメモ帳で開き、次のようにする（**先にフォルダのバックアップを取る**）
   ```
   enable-rcon=true
   rcon.password=（好きなパスワード）
   rcon.port=25575
   ```
2. サーバーを起動し直す
3. 管理画面の「設定」→「Minecraft」で「Minecraftを使う」にチェック、プレイヤー名を入れて「保存」
4. 「秘密情報」の「RCONのパスワード」に、1. と同じパスワードを入れて「秘密情報を保存」
5. 「テスト」画面の「Minecraftのコマンドを試す」で `say テスト` を「今すぐ実行」→ ゲームのチャットに出れば成功

## VOICEVOX の準備

1. VOICEVOX を起動しておく
2. 管理画面の「設定」→「読み上げ」で「読み上げを使う」にチェック、「一覧を読み込む」で話者を選んで「保存」
3. OBSに「読み上げ」オーバーレイを入れる（上の表）
4. 「テスト」画面の「読み上げを試す」→ 配信の音（OBSの音声ミキサー）に出れば成功

配信で使う時は、キャラクターごとの利用規約に従い、概要欄などにクレジット（例：`VOICEVOX:ずんだもん`）を書いてください。

## フェーズ0の確認（短いテスト配信でやること）

要件定義書「9. 開発フェーズ」のフェーズ0の完了条件です。

1. 本体を起動して、管理画面のTikTokが「配信待ち」になっていることを見る
2. TikTokで短いテスト配信を始める → 1分ほどで「接続中」になり、「直近のイベント」にコメントや入室が出る
3. 配信中に、自分（または協力してくれる人）から小さいギフトを送る → OBSにアラートが出る／Minecraftにコマンドが届く／読み上げが聞こえる
4. 配信を終える → 管理画面の「記録」に配信が1行増え、「配信中」でなくなる
5. 「記録」→「フェーズ0の確認」の数字をメモする
   - **入室の通知が届いた割合**：来場者のうち入室の通知も届いた人の割合。100%に近いほど、入室の通知は全員分届いている
   - **TikTokの累計視聴者** と **来場者** の差
   - **Euler Stream**：接続1回あたりの回数（「うち 接続の署名」÷「接続できた回数」）、配信待ちの確認で使った回数
6. 5. の結果を Claude Code に伝えて、要件定義書に書き足してもらう

テスト配信をしなくても、「テスト」画面で、にせのギフトなどを起こして演出・コマンド・読み上げを確かめられます（記録には「テスト」の印が付き、本番の集計には入りません）。

## 更新のしかた

1. 管理画面で「終了」を押す（`update.bat` が聞いてくるので、そこで終了してもよい）
2. プロジェクトのフォルダの **`update.bat`** をダブルクリック（GitHubから最新をもらって、`setup.bat` まで自動でやります）
3. デスクトップの「TikTok LIVE ツール」で起動し直す

## TikTokにつながらなくなった時

TikTokには公式の配信イベントAPIがないため、TikTok側の変更で急につながらなくなることがあります（要件 N-6）。
多くの場合、接続に使っている部品（tiktok-live-connector）を新しくすれば直ります。

1. 管理画面で「終了」
2. プロジェクトのフォルダで PowerShell（または Claude Code）から：
   ```
   npm install tiktok-live-connector@latest
   npm test
   ```
3. 起動し直して、つながるか確かめる
4. 直らない時は、Claude Code に「TikTokにつながらない。ログを見て」と頼む（接続の処理は `src/server/tiktok/` にまとめてあります）

## データの場所とバックアップ

- **配信の記録（データベース）と設定**：`%LOCALAPPDATA%\TikTokLiveTool`
  （例：`C:\Users\あなた\AppData\Local\TikTokLiveTool`。管理画面の「記録」→「データのフォルダを開く」）
  - プロジェクトのフォルダとは別の場所にあるので、プロジェクトを消したり取り直したりしても、記録は消えません
  - `live.db`：配信の記録 ／ `settings.json`：設定 ／ `logs`：動作のログ ／ `backups`：バックアップ
- **バックアップ**：毎日1回、自動で `backups` に作られます（14日分）。設定で、Googleドライブの同期フォルダなど、別の場所にもできます
- **秘密情報**：プロジェクトのフォルダの `.env`（Gitには入りません）
- 記録は配信PCの中だけにあり、外部には送りません。特定の視聴者のデータを消したい時は、Claude Code に頼んでください

## 困った時

- 管理画面の「ダッシュボード」の下に「最近の注意・エラー」が出ます（何が起きたか・どうすれば直るか）
- 詳しいログ：データフォルダの `logs\app-日付.log`（管理画面の「記録」→「ログのフォルダを開く」）
- 起動できない時のログ：`%TEMP%\tiktok-live-tool-start.log`
- Claude Code に「ログを見て原因を調べて」と頼むと、調べてくれます

## 配信データの分析

Claude Code に「先月の常連を教えて」「一番盛り上がった配信は？」などと頼むと、データベースを読み取り専用で調べて答えます。
自分で調べる時は、プロジェクトのフォルダで：
```
npm run query -- "SELECT * FROM streams ORDER BY started_at DESC LIMIT 5"
```
（表の説明と例は [docs/database.md](docs/database.md)）

## 開発者（Claude Code）向け

| コマンド | 内容 |
|---|---|
| `npm start` | 本体を起動（コンソールあり） |
| `npm run dev` | 本体を起動し、ファイルを変えたら自動で再起動 |
| `npm run dev:admin` | 管理画面の開発用サーバー（http://localhost:5173 。本体も起動しておく） |
| `npm run build` | 管理画面を作る（`dist/admin`） |
| `npm test` | 自動テスト |
| `npm run typecheck` | 型チェック |
| `npm run query -- "SQL"` | データベースを読み取り専用で調べる |

- 本体（`src/server`）は、ビルドせずに Node.js が TypeScript をそのまま動かします（型を読み飛ばす方式。`enum` など読み飛ばせない書き方は使えません）
- フォルダの構成：
  - `src/server/tiktok` … TikTok接続（ライブラリを使うのは `connectorClient.ts` だけ）
  - `src/server/db` … データベース（表の構造は `migrations.ts`）
  - `src/server/actions` … オーバーレイ・Minecraft・読み上げ
  - `src/server/rules` … ルール（フェーズ0は試作の1つだけ）
  - `src/admin` … 管理画面（React）
  - `overlays` … オーバーレイ（素のHTML/CSS/JS。新しいものは `_template` をコピー）
  - `tests` … 自動テスト
